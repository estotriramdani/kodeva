## Commit Message Guidelines

Use the following format for commit messages:

```
<type>(<scope>): <subject>
<BLANK LINE>
<body>
<footer>
```

Where:
- `<type>` is the type of change (e.g., feat, fix, docs, style, refactor, test, chore)
- `<scope>` is the scope of the change (e.g., component name, file name)
- `<subject>` is a short description of the change
- `<body>` is a detailed description of the change
- `<footer>` is any additional information about the change

## Commit Frequency

Commit frequently to keep the history clean and to avoid large, difficult-to-review changes.

Note: If you are working on a large feature, consider breaking it down into smaller, incremental commits.

You don't need to wait instructions from a reviewer to commit your work. If you have a change that is ready to be committed, go ahead and commit it.
